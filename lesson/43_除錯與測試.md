# 第 43 課：除錯與測試——讓程式的結果值得相信

> **本課主題：用小而有目的的測試資料，找出程式沒有立刻報錯但結果不對的問題。**
>
> 程式能執行不代表答案一定正確。測試是在問：「我有沒有用足夠不同的情況檢查規則？」

## 今課可以做到甚麼？

- 分辨語法錯誤、執行期錯誤和邏輯錯誤；
- 為一個小函式設計正常、邊界和特殊測試；
- 使用 `assert` 為預期結果建立自動檢查。

## 開始前：想一想

「計算購物車總價」在 `[10, 20]` 得到 30，是否已證明程式正確？空購物車、只有一件商品、價格為 0 的商品又會怎樣？

## 新概念

### 1. 三類常見問題

- **語法錯誤**：Python 看不懂寫法，例如漏了冒號或括號；
- **執行期錯誤**：程式運行到某行才出錯，例如索引超出範圍；
- **邏輯錯誤**：程式能跑完，但答案不符合規則。這類最需要測試資料。

### 2. 三種基本測試

- **正常值**：一般會遇到的輸入；
- **邊界值**：剛好在規則門檻，例如 0 或 60；
- **特殊值**：空 List、重複資料等容易被忽略的情況。

## 跟著做：例子 1——為總價函式寫測試清單

```python
def total_price(prices):
    total = 0
    for price in prices:
        total = total + price
    return total

cases = [
    ([10, 20], 30),
    ([0, 15], 15),
    ([], 0)
]

for prices, expected in cases:
    actual = total_price(prices)
    print(prices, "預期：", expected, "實際：", actual)
```

### 預期輸出

```text
[10, 20] 預期： 30 實際： 30
[0, 15] 預期： 15 實際： 15
[] 預期： 0 實際： 0
```

### 逐行解釋

`cases` 的每一項都是一個 Tuple：第一項是輸入，第二項是人手算好的預期答案。迴圈把函式的實際結果和預期結果一起顯示，方便比較。

空 List 是重要測試：它能檢查程式是否真的以 `0` 作為未有任何價格時的總價。

## 再試一次：例子 2——用 assert 自動指出不符合預期的結果

```python
def reaches_target(gold):
    return gold >= 60

assert reaches_target(60) is True
assert reaches_target(59) is False
assert reaches_target(100) is True

print("全部測試通過")
```

### 預期輸出

```text
全部測試通過
```

`assert` 後面的條件必須是 `True`。若你把 `gold >= 60` 錯寫成 `gold > 60`，剛好等於門檻的第一個測試便會失敗，程式會指出有檢查不符合預期。

## 易錯位

### ❌ 只測一組「看起來正常」的資料

這容易漏掉空資料、剛好等於門檻或重複值。

**✅ 修正：** 至少準備一組正常值、一組邊界值和一組特殊值。

### ❌ 看到錯誤訊息就只複製最後一行

錯誤訊息上方通常顯示檔案、行號和呼叫過程。

**✅ 修正：** 先讀最後一行了解錯誤名稱，再回到指出的行查看變數和規則。

### ❌ 為了讓 assert 通過而改預期答案

**原因：** 測試的工作是檢查規則，不是把答案遷就程式。

**✅ 修正：** 先手算並確認規則；再決定要修正程式還是修正原本理解。

## 本課小結

1. 不報錯的程式仍可能有邏輯錯誤。
2. 測試要覆蓋正常、邊界和特殊情況。
3. `assert` 能把預期規則變成可重複執行的檢查。
