## 新概念

### 1. 三類常見問題

- **語法錯誤**：Python 看不懂寫法，例如漏了冒號或括號。
- **執行期錯誤**：程式開始運行後才出錯，例如讀取不存在的 Dictionary key。
- **邏輯錯誤**：程式能運行，但答案不是題目要求的答案。

### 2. 測試不是只試一次

一個有用的測試組合至少包括：

- **正常值**：最常見的情況；
- **邊界值**：例如剛好 60 分、空清單、0；
- **特殊值**：重複資料、很大的數、格式不整齊的輸入。

錯誤訊息最重要的部分通常是最後幾行：它會告訴你錯誤名稱、出錯位置和原因。

## 跟著做：例子 1——為計算總價寫測試

```python
def calculate_total(prices):
    total = 0
    for price in prices:
        total = total + price
    return total

print(calculate_total([12, 8, 5]))

assert calculate_total([10, 20]) == 30
assert calculate_total([]) == 0
assert calculate_total([0, 5]) == 5
print("所有測試通過")
```

### 預期輸出／結果

```text
25
所有測試通過
```

### 逐行解釋

`assert 條件` 會檢查條件是否為真。測試成功時通常不會額外顯示內容；若答案錯誤，程式會在那一行停止並顯示 `AssertionError`。三個測試分別涵蓋一般資料、空清單和含有 0 的資料。

## 再試一次：例子 2——處理可能不存在的資料

```python
scores = {"Amy": 82, "Ben": 76}
name = input("輸入學生姓名：").strip()

if name in scores:
    print(f"{name} 的分數是 {scores[name]}")
else:
    print("找不到這位學生，請檢查拼寫。")
```

### 這次改了甚麼？

若直接寫 `scores[name]`，而輸入的名字不存在，會出現 `KeyError`。先用 `in` 檢查，便可把錯誤情況變成清楚的提示。

## 易錯位

### ❌ 只測試一個「看來正常」的例子

**原因：** 一個成功案例不能證明所有情況都正確。

**修正方法：** 每次至少補上邊界值和特殊值。

### ❌ 看見錯誤訊息便全部複製到搜尋器

**原因：** 錯誤訊息包含出錯檔案、行號和錯誤種類，這些正是定位問題的線索。

**修正方法：** 先讀最後一行的錯誤名稱，再回到指定行檢查變數和符號。

### ❌ 為了不報錯而把 `except:` 包住全部程式

**原因：** 這會把真正的問題隱藏起來，之後更難修正。

**修正方法：** 先找出原因；只在知道預期會出現甚麼錯誤時才作針對性處理。
