# 第 33 課：訓練模型——讓模型由錯誤中調整

> **本課主題：讓模型反覆預測、量度錯誤和更新參數，逐步接近訓練資料的規律。**
>
> 上一課的權重和偏差暫時是人手指定的數字。訓練就是讓模型根據答案與預測的差距，自己微調它們；但訓練集表現變好，仍不代表面對新資料一定可靠。

## 今課可以做到甚麼？

- 執行一個最小 PyTorch 訓練迴圈；
- 讀出 loss 由大變小的過程；
- 按正確次序說出訓練中的五個步驟。

## 開始前：想一想

若你每次估答案後都知道自己差多少，便可以下次調整得更接近；若只知道「對／錯」，改善方向會少很多。

模型同樣用一個數字量度差距，再根據差距調整權重。這個差距數字叫 loss。

## 新概念

### 1. Loss：預測與答案差多遠

Loss 用一個數字量度模型預測和正確答案的差距。回歸問題常用 `MSELoss`；數字越小，表示模型在**目前訓練資料**上通常較接近答案。

### 2. 一輪訓練的固定次序

1. 模型根據輸入作預測；
2. 用 loss 比較預測和答案；
3. 清除上一輪留下的梯度；
4. 由 loss 計算本輪應調整的方向；
5. optimizer 更新權重和偏差。

![同一個線性模型在多輪訓練中，loss 逐步下降並更新權重](/images/lesson-33-training-loss-gradient.svg)

`loss.backward()` 和 `optimizer.step()` 是 PyTorch 把第 4、5 步完成的指令。本課先記住它們的位置和作用，不需要手算所有微積分。

## 跟著做：例子 1——讓模型學習 `y = 2x + 1`

```python
import torch
from torch import nn

torch.manual_seed(0)

x = torch.tensor([[1.0], [2.0], [3.0], [4.0]])
y = torch.tensor([[3.0], [5.0], [7.0], [9.0]])

model = nn.Linear(1, 1)
loss_fn = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.05)

for epoch in range(201):
    prediction = model(x)
    loss = loss_fn(prediction, y)

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

    if epoch in [0, 50, 100, 200]:
        print("第", epoch, "輪 loss：", round(loss.item(), 4))
```

### 預期輸出／結果

畫面會列出四個 loss。第一輪較大，之後通常會逐步變小並接近 0，因為資料遵從簡單規律 `y = 2x + 1`。

`torch.manual_seed(0)` 令本例的隨機初始值固定，方便全班比較結果；真實專題不能只因一個 seed 成績好就下結論。

### 逐行解釋

`model = nn.Linear(1, 1)` 建立一個「一個輸入、一個輸出」的線性模型。每一輪都先計算 `prediction` 和 `loss`。

接著必須先 `optimizer.zero_grad()`，避免前一輪的梯度累積；`loss.backward()` 計算調整方向；`optimizer.step()` 按設定的 learning rate 更新模型參數。

## 再試一次：例子 2——用訓練後模型預測新數字

**先完整執行例子 1**，再加入以下程式：

```python
new_x = torch.tensor([[5.0]])
new_prediction = model(new_x)

print("x = 5 時的預測：", round(new_prediction.item(), 2))
```

結果應接近 `11`。這表示模型已從這四筆訓練資料學到大致線性規律；它不是證明模型已能處理所有不同情況。

## 易錯位

### ❌ 忘記 `zero_grad()`

PyTorch 預設會累積梯度；若不清除，下一輪更新會混入之前的調整資訊。

**✅ 修正：** 每輪在 `loss.backward()` 前呼叫 `optimizer.zero_grad()`。

### ❌ 把 loss 下降理解成模型已完全可靠

本例只有四筆規律很整齊的資料。真實資料可能有噪音、缺漏和不同情況，仍要保留未見資料評估。

### ❌ 把 learning rate 調得很大

步幅太大可能令 loss 上下跳動甚至變大；太小又會學得很慢。
