## 開始前：想一想

聊天模型能寫出很像答案的句子，是否代表每一個事實都已查證？語句流暢和內容正確是兩件不同的事。

## 新概念

### 1. Transformer 與 LLM

文字先被切成 token。模型根據前文 context 預測下一個 token，反覆產生句子。Transformer 的注意力機制幫助模型在長輸入中衡量不同 token 的關係。

### 2. 音訊資料

數碼音訊是一連串時間取樣值；常轉成 spectrogram 等特徵，讓模型觀察時間和頻率模式。不同取樣率、噪音和錄音設備會影響結果。

## 跟著做：例子 1——用程式觀察簡單文字 token

```python
text = "Python can analyze data"
tokens = text.lower().split()

print(tokens)
print(len(tokens))
```

### 預期輸出／結果

輸出一個詞語 List 和數量。真實 LLM 的 tokenizer 較複雜，未必以完整英文詞語分割；這只是概念示範。

### 逐行解釋

本例沒有呼叫任何大型模型，只用 `split()` 幫助理解「文字會先被拆成較小單位」這件事。

## 再試一次：例子 2——建立事實核查清單

```python
answer = "模型產生的一段說法"
checks = ["有沒有來源？", "是否可由可靠資料核對？", "是否涉及敏感建議？"]

for question in checks:
    print(question)
```

這不是模型驗證程式，而是提醒：使用生成式 AI 的內容時，應特別核對事實、數字、引用和高風險建議。

## 易錯位

### ❌ 把模型輸出當成引用來源

模型可產生看似合理但不存在的書目、數字或網址。需要引用時，應回到可靠原始來源核實。

### ❌ 上傳個人或機密資料到不明服務

處理同學資料、考試內容、帳戶資料前，先了解平台私隱設定與學校規則。

## 本課小結

1. LLM 根據 context 逐步預測 token，不保證每項內容正確。
2. 生成內容應核查來源、數字與高風險建議。
3. 音訊 AI 同樣需把訊號轉為可學習的數字特徵。
