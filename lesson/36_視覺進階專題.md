## 新概念

### 1. Batch 與 DataLoader

圖片很多時不會一次全部送入模型。DataLoader 每次提供一小批資料，節省記憶體並便於打亂訓練順序。

### 2. 評估模式

訓練用 `model.train()`；評估用 `model.eval()` 和 `torch.no_grad()`。這會影響 dropout 等層，也避免不必要的梯度計算。

## 跟著做：例子 1——建立 DataLoader 和一輪訓練骨架

```python
from torch.utils.data import DataLoader
from torch import nn
import torch

loader = DataLoader(train_data, batch_size=64, shuffle=True)
model = nn.Sequential(nn.Flatten(), nn.Linear(28 * 28, 10))
loss_fn = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)

for images, labels in loader:
    logits = model(images)
    loss = loss_fn(logits, labels)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    break

print(loss.item())
```

### 預期輸出／結果

本例只訓練第一個 batch，目的是看懂程式結構。真正專題需要跑多個 epoch 並在驗證／測試資料評估。

### 逐行解釋

`CrossEntropyLoss` 適合多分類的原始輸出 logits；因此最後一層不必先加 softmax。`break` 只為縮短示範，不應留在完整訓練程式。

## 再試一次：例子 2——以評估模式作預測

```python
model.eval()
with torch.no_grad():
    logits = model(image.unsqueeze(0))
    prediction = logits.argmax(dim=1).item()

print("預測類別編號：", prediction)
```

`argmax(dim=1)` 取出每張圖片分數最高的類別位置。模型輸出仍需配合類別名稱和測試結果解讀。

## 易錯位

### ❌ 訓練時保留 `break`

這會讓模型每次只見到一小批資料，難以學習整個資料集。

### ❌ 只展示答對的例子

專題也應展示幾個錯誤例子，找出相似類別、模糊圖片或資料不足等可能原因。
